# Daybook — notes for Claude

Personal planner PWA (tasks, calendar, people/catch-ups, journal, notes, AI assistant, push reminders).
The owner uses it mainly as an **iPhone home-screen app**; desktop web must keep working too.
Production: https://daybook-smoky-seven.vercel.app · Repo: github.com/amaanhafeez18/daybook

## Working agreement
- For every change: `git pull` on `main` → new branch → make the change → `npm run build` (and `node --check api/*.js`) → test in the browser pane → commit → push → `gh pr create` → wait for the Vercel check (`gh pr checks <branch> --watch`) → **merge it** (`gh pr merge --merge --delete-branch`) → back to `main` and pull. The owner has asked for auto-merge.
- Merging to `main` deploys to production. Anything that needs a Supabase schema change: write a migration in `supabase/migrations/` and give the owner the SQL to run **before** relying on it. Code must keep working if the migration hasn't been run yet (see "tolerant" below).
- Never paste or print secrets. The owner enters keys in Vercel/Supabase themselves. Never enter passwords into the app.
- When testing against the live DB, back up what you touch, use `zz-` prefixed test data, and remove it afterwards (including test messages in the assistant chat history).
- Explain things simply; the owner is new to PRs and deployment.

## Run locally
- `npm run dev:full` → `vercel dev` (Vite + `/api` functions) on http://localhost:3000. `npm run dev` is frontend only.
- **Cloud sessions** (Linux, keys in the environment, no `gh`: use the GitHub MCP tools): the SessionStart hook puts Node 20 on PATH (tests need it). `npm run dev:cloud` (`scripts/dev-cloud.mjs`) = Vite + `/api` handlers on :3000 without `vercel dev`; it re-runs itself on `/opt/node22` with `NODE_USE_ENV_PROXY=1` because Node's fetch ignores the egress proxy (any other script that calls Supabase/OpenAI needs the same). Restart it after editing `api/`. Test only as `zz-claude` (password unknown on purpose): `NODE_USE_ENV_PROXY=1 /opt/node22/bin/node scripts/test-login.mjs zz-claude` prints a token (zz- accounts only; signed with the cloud `JWT_SECRET`, so useless on production) → Playwright `addInitScript` sets `localStorage['daybook.session.token']`, then load the page (a hash change alone doesn't re-read it). Playwright: `require('/opt/node-tools/node_modules/playwright')`.
- `npm test` → `node --test tests/` (gym scheduling, stats, store cache). Run it with the build before every PR.
- Local secrets live in `.env` (git-ignored; `vercel dev` reads `.env`, not `.env.local`). Browser-pane launcher: `.claude/launch.json` (name `daybook`).
- Editing `vite.config.js` or `.env` requires restarting the dev server (vercel dev's proxy breaks after Vite restarts).
- Windows machine: Bash heredocs choke on apostrophes/quotes in long scripts — write scripts to a file (e.g. `.claude/tmp.py`, then delete) or use the Edit tool. PowerShell here-strings break on quotes too; use `--body-file` for PR bodies.

## Architecture
- **Frontend** (`src/`): React 18 + Vite 5, hash routes (`#/today`, `#/tasks`, `#/calendar`, `#/people`, `#/assistant`, `#/journal`, `#/health`, `#/gym…`, `#/food…`, `#/settings`). `App.jsx` = shell (auth, nav, lazy-loaded pages, sync badge, iOS-style title bar).
  - **Spaces + areas:** phones have two spaces, each with its own tab bar — **Plan** (Today, Tasks, Calendar, People, Assistant; Journal is the top-bar icon) and **Health** (Today = `pages/HealthPage.jsx` with the gym/food/weight cards, Gym, Food, Assistant) — switched by the `Plan | Health` pill in the top bar (`SpaceSwitch`; prefs `space`, `space.plan`, `space.health` remember where you were). Plan → Today shows a one-line-per-area `HealthGlance` instead of the big cards. `lib/areas.js` = optional areas (people, journal, gym, food) in `settings.areas` (missing = on), switched in Settings → "What you use" (`#/settings/areas`), set by the welcome tour's picks, respected by the nav, Today, the assistant prompts and server reminders. With gym and food both off there's no Health space or pill. Desktop: sidebar groups. Never add a global "advanced mode".
  - `lib/store.js` — shared data store. Renders from localStorage cache, refreshes with one `GET /api/data?keys=…`, edits apply immediately and save as **PATCH diffs** (lists: `{key, upsert, delete}`; settings: `{key:'settings', set}` field-level). Retries offline, flushes when backgrounded. Use `useData(key)`, `updateData`, `updateSettings`.
  - **Gym tracker:** `pages/GymPage.jsx` routes `#/gym/<view>/<param>` to `pages/gym/*`. Pure modules in `lib/gym/` (`schedule.js` has zero imports and is also imported by `api/` — keep it and `library.js`/`stats.js`/`units.js` free of browser/React code); `lib/gym/state.js` is the client glue (settings.gym, sessions, active workout in localStorage + `settings.gym.active`). Design docs: `.claude/gym-spec.md`, `.claude/gym-contract.md` (local only). The UI says "shift" (not "push") for moving the schedule forward. Weights are stored in kg. **Missed workouts move on** (`prefs.carryMissed`, default on; Gym settings → Week; assistant `gym_update_prefs.carry_missed`): `schedule.js` `applyCarry` treats a past planned-routine day with no session, skip, shift or override as a shift (from `prefs.carryFrom`, else `CARRY_SINCE` 2026-10-20), computed per call in `dayContext(gym, sessions, today)`; such a day resolves `status: 'skipped'`, `carried: true`, and the day it moved to has `carriedFrom` ("Missed yesterday" badge). So anything reading the plan must pass sessions: `resolveDay/resolveRange/nextWorkout` do; `plannedFor`, `realign`, `replaceRoutineWithRest` take an optional `{ gym, sessions, today }`. **Reorder in a workout:** press and hold an exercise card's title row (not ⋯; 420 ms, a moving finger scrolls) → every card folds to its title (`.gym-ex.is-folded`, same elements, so the touch carries on) and that card is dragged at once (`useDragSort` `pickUp(key, pointer)`; a non-passive touchmove on the list blocks scrolling while held); on drop the order saves once (`useLocalReorder` → `actions.reorder`), the cards unfold with the moved one centred, and the release click is swallowed. ⋯ → Reorder exercises (the compact list with grips/arrows) stays for keyboards.
